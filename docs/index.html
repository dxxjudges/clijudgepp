为判题工作流设计

不是把命令行套一层壳：题目、测试点、比赛、提交记录都是原生控件，评测在后台线程执行，界面全程不阻塞。

C++

复用主项目数据层

直接 include CliJudge 的 ProblemStore、ContestStore、judge.h，题目格式、判题逻辑与 CLI 完全一致，不存在两套实现漂移。

⇄

与命令行数据互通

与 main/ 项目同目录时自动识别其 data/；写入时持有同一把 .clijudge.lock，GUI 与 CLI 可以并存使用。

#

Markdown 题面渲染

自写解析器 + DrawList 绘制：标题、列表、代码块、表格对齐、引用、粗斜体、行内代码与链接，中英文逐字断行。

▶

异步评测

提交后立刻返回界面，判题在后台线程跑多个测试点；结果页展示子任务与逐点耗时、内存、编译错误。

⌘

单文件、零运行时

Windows 是静态链接的单文件 exe，Linux 只依赖系统库；不用装 .NET、Node 或浏览器。内存占用以 MB 计。

▣

同一套代码上手机

Android 端复用同一 UI 与数据层，横屏平板式布局，可浏览题库、文章、比赛与提交记录。

快速开始

把 GUI 仓库与 CliJudge 主项目放在同一目录即可共享数据，构建时会自动获取 SDL2。

# 目录结构：两个仓库平级
workspace/
├── clijudge/      # CLI 主项目（include 源 + data/）
└── clijudgepp/    # 本仓库

# 构建桌面版
git clone --recursive https://github.com/dxxjudges/clijudgepp.git
cd clijudgepp
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j

./build/clijudgepp            # 启动图形界面
./build/clijudgepp --selftest  # 数据目录探测冒烟

数据目录优先级

按以下顺序探测，命中即用；也可以用 gui.json 或 --data-dir 显式指定。 

// 可执行文件同目录的 gui.json
{
  "data_dir": "D:/judgelite/main/data",
  "font_path": "",
  "window_width": 1280,
  "window_height": 800
}
探测顺序：显式路径 → 同级 clijudge/main 主项目 → 已存在的数据目录 → 平台默认目录。

Android：管理与浏览

手机上无法运行 g++ 与沙箱，因此移动端定位是随身题库：查看题面、比赛与历史提交。提交页会明确提示不支持本地编译评测。

  • 默认横屏（sensorLandscape），自动切换左右方向
  • 自带中文字体探测，Android 系统字体直接加载
  • Markdown 题面、表格、代码块完整渲染
  • 数据保存在应用私有目录，卸载即清除；allowBackup 已关闭
  • APK 含 arm64-v8a / armeabi-v7a / x86_64，约 18 MB
下载 APK app-debug.apk 
# 本地构建 APK（JDK 17 + SDK 34 + NDK 26.1）
cd android
./gradlew assembleDebug

# 产物
app/build/outputs/apk/debug/app-debug.apk

# 安装到已连接的设备
adb install -r app/build/outputs/apk/debug/app-debug.apk
CI 发版时会把 v* 标签同步为 APK 的 versionName，versionCode 取运行序号。
